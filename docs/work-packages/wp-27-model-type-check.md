# WP-27 Abgleich C#-Modell ↔ DB: Typen, NULL, Längen → Release 3.10.0
Backlog-Eintrag des Nutzers (2026-10-07, „Kandidat direkt nach WP-20“), gestartet 2026-10-08. Bis dahin meldete `ClrModelMapping` nur Namen (fehlende Tabellen/Spalten, Spalten ohne Property, Groß-/Kleinschreibung).
- ModelHost (`PropertyExport`, Format-Version **2** → vorhandener Modell-Cache wird einmal neu aus dem Projekt gelesen): `MaxLength`, `Precision`, `Scale` **nur wie konfiguriert** (`GetMaxLength()`/`GetPrecision()`/`GetScale()`; bei explizitem `HasColumnType` die Facetten der daraus geparsten `RelationalTypeMapping`, z. B. `CHAR(1)` → 1). Die Provider-Vorgaben (`NVARCHAR2(2000)` für jeden String) hätten fast jede Spalte abweichen lassen. `ColumnNullable` = `IsColumnNullable(StoreObject)`: EFs Sicht auf die Spalte, berücksichtigt TPH (Pflicht-Property eines abgeleiteten Typs → nullable Spalte) und optionale Owned Types.
- Core: `ISchemaReader.GetColumnNamesAsync` → `GetColumnsAsync` (volle `ColumnInfo` je Tabelle, weiter eine Abfrage pro Schema; ohne `DATA_DEFAULT` – LONG zählt mit 32 KB je Zeile in die Fetch-Größe – und ohne Kommentare). `ColumnTypeCheck` (rein, Unit-Tests) vergleicht je zugeordneter Property:
  - **Typ** (Fehler): gespeicherter CLR-Typ nach dem Converter (`ProviderClrType`, auch EFs eigener Enum-Converter) gegen die Oracle-Kategorie; bei `bool` ohne Converter auf Text „fehlt der Converter?“. `DateTime` auf `TIMESTAMP WITH TIME ZONE` Hinweis, Guid auf `RAW(n≠16)` Warnung. Unbekannte CLR-Typen und XMLTYPE/JSON/Objekttypen werden übersprungen.
  - **NULL**: Spalte nullable, Modell Pflicht → Warnung (EF wirft beim Lesen); Spalte NOT NULL, Modell optional → Warnung (ORA-01400), außer Identity, `DEFAULT ON NULL`, virtuelle Spalten und **`string`/`byte[]`** (Hinweis des Nutzers: kein Problem – Oracle speichert einen leeren Wert als NULL, eine Pflicht-Property hielte NULL also auch nicht fern; Lesen geht immer). Die Gegenrichtung (Pflicht-String auf nullable Spalte) bleibt eine Warnung.
  - **Länge** (nur konfiguriert, nur Tabellen): länger als die Spalte → Warnung (ORA-12899, auch RAW); BYTE-Semantik mit gleicher Länge → Hinweis (nicht bei Convertern: deren Werte sind ASCII); kürzer → Hinweis.
  - **Stellen**: Ganzzahl auf `NUMBER` mit Nachkommastellen oder größerer Precision als der Typ fasst (int 10, long 19 …), auf `FLOAT`/`BINARY_*` → Warnung; `decimal` mit konfigurierter Precision: weniger Vorkommastellen in der Spalte → Warnung (ORA-01438), weniger Nachkommastellen → Warnung (Oracle rundet), sonst abweichend → Hinweis; ohne Konfiguration nur `NUMBER(p > 28)`.
  - Views/MViews werden nur gelesen: nur Typ und NULL, NULL dort als Hinweis (Oracle meldet berechnete View-Spalten immer als nullable).
  - Bewusst **nicht** gemeldet: `NUMBER` ohne Precision bei Ganzzahlen (bei Schlüsseln üblich, der Provider bildet `int` selbst auf `NUMBER(10)` ab – wäre beim Nutzer massenhaft Rauschen); nicht konfigurierte Längen.
  - `ClrModelMapping.ColumnMismatches` (Schwere → Entity → Spaltenposition), `MismatchesOf(table, column)`.
- UI: Abschnitt „Typen, NULL und Längen“ auf der Modell-Seite (`ModelMismatches`: Schwere als Kürzel „Typ/NULL/Länge/Stellen“ in Rot/Orange/Grau, Häkchen je Schwere, Suche, Spalte als Link in die Spalten-Ansicht), Chip „N Abweichungen bei Typ/NULL/Länge“ (ohne Hinweise). Spalten-Ansicht: Kürzel hinter der Property mit den Meldungen im Tooltip. Statusleiste „C# · … · N Abw.“ zählt Fehler und Warnungen mit.
- Beispielmodell: bewusster Drift `Artikel.Bezeichnung` `HasMaxLength(200)` gegen `VARCHAR2(100 CHAR)` (wie `Kunde.Email`); dazu ergeben sich `Kunde.Kuerzel` (`CHAR(3 BYTE)`) und `KundeAuftraegeView.Anzahl` (COUNT in der View) als Hinweise.
- Tests: Unit (`ColumnTypeCheckTests`, Mapping mit typisierten Spalten), Integration (Spaltenabfrage gegen `GetDetailsAsync`, ModelHost exportiert die Facetten des Beispielprojekts inkl. `HasColumnType("CHAR(1)")`, Abgleich gegen echte Spalten).
- E2E (eigener Container `ferret-wp27`, Beispielprojekt verknüpft, hell/dunkel): Abschnitt mit drei Einträgen, Filter je Schwere und Suche, Link öffnet ARTIKEL in „Spalten“ mit Kürzel und Tooltip, Statusleiste „4 Abw.“, erneutes Verbinden lädt das Modell im neuen Format aus dem Cache. Log ohne `[ERR]`.

# WP-49 Bilder im Changelog ([#15](https://github.com/JuliusFo/FerretSharp/issues/15)) → Release 3.34.0
Vom Nutzer am 2026-10-14 eingeplant und am selben Tag auf `feat/update-notes-all-versions` mit umgesetzt (statt `wp/49-changelog-images`): Beide fassen den Update-Dialog an, und je früher die Unterstützung erscheint, desto weniger Installationen zeigen „!Alt-Text“. Plan unten; Regel für Autoren in `docs/release.md` › Bilder im Changelog.

## Entscheidungen des Nutzers (2026-10-14)
- Alle Vorschläge aus der Durchsicht übernommen: Bildzeile immer eigener Block (auch eingerückt unter einem Punkt), Adresse per `Uri` prüfen, Repo-Test in Core (läuft im Release-Workflow), eine Zeile Doku zum Laden von GitHub, Klick öffnet das Bild im Browser.
- Hell/dunkel: eine Variante, **dunkel** („wir arbeiten eh alle im Keller“).

## Gebaut
- `ReleaseNotes` (UI/State): Blockart `Image` mit `NoteBlock.Image` (Uri). Eine Zeile, die nur aus `![alt](url)` besteht, schließt den Block davor ab. `IsOwnImage`: https, Host genau `raw.githubusercontent.com`, Standard-Port, kein UserInfo/Query/Fragment, Pfad unter `/JuliusFo/FerretSharp/` mit mindestens zwei Segmenten aus `[A-Za-z0-9._-]` (kein `.`/`..`, keine Escapes wie `%2e`). Sonst ein Absatz mit dem Alt-Text, ohne Alt-Text nichts. Ein Bild mitten im Satz bleibt Text („!alt“) wie bisher.
- `UpdateDialog`: `<a class="note-image" target="_blank">` um `<img loading="lazy">` (Link geht über `UrlLoading` in den Browser, nur https); `@onerror` merkt sich die Adresse, dann steht der Alt-Text als Hinweis da. CSS: `max-width: 100%`, `max-height: 320px`, Rahmen.
- `release.yml`: Bildzeilen im ausgeschnittenen Abschnitt auf `https://raw.githubusercontent.com/JuliusFo/FerretSharp/$TAG/<pfad>` umgeschrieben (vor `changes.md` und `notes.md`); bricht ab bei einem Pfad, der nicht direkt unter `docs/images/changelog/` liegt, oder einer fehlenden Datei. Lokal mit Windows PowerShell 5.1 geprüft (Umschreiben, eingerückte Zeile, Bild im Satz bleibt, beide Abbrüche).
- Tests: `ReleaseNotesTests` (Bildzeile unter einem Punkt, 12 fremde oder verbogene Adressen, ohne Alt-Text, Bild im Satz), `ChangelogTests` (Core: der echte CHANGELOG; die Prüfung selbst an einer Testdatei mit jeder Fehlerart). Nebenbei `tests/Shared/Repository.cs` (`Repository.Root`) statt vier Kopien der Suche nach `FerretSharp.slnx`.
- Doku: `docs/release.md` › Bilder im Changelog, `docs/e2e-testing.md` › Updates, README (Dialog lädt Bilder von GitHub).

## Planung (aus `docs/roadmap.md`)
(Vom Nutzer am 2026-10-14 nach einer Bewertung eingeplant.) Branch `wp/49-changelog-images`. Der Changelog erscheint an drei Stellen: `CHANGELOG.md` im Repo (Bilder gehen schon, auch relativ), Text des GitHub-Releases (`notes.md` aus `release.yml`, relative Pfade laufen dort ins Leere) und Update-Dialog der App (`changes.md` → `vpk pack --releaseNotes` → `NotesMarkdown` → `ReleaseNotes.Parse`; `![alt](url)` wird heute als Link gelesen und zeigt „!alt“).
- **Ablage:** Bilder im Repo (Vorschlag `docs/images/changelog/<version>-<name>.png`), im `CHANGELOG.md` relativ eingebunden, eine Zeile je Bild. Keine GitHub-Anhänge (nicht versioniert, nur von Hand hochzuladen) und keine Release-Assets (stünden zwischen Setup.exe und den Paketen).
- **Release-Workflow:** Beim Ausschneiden des Abschnitts relative Bildpfade auf `https://raw.githubusercontent.com/JuliusFo/FerretSharp/vX.Y.Z/<pfad>` umschreiben (am Tag, ändert sich nicht mehr) – für `changes.md` und `notes.md`. Der Schritt bricht ab, wenn ein verwiesenes Bild im Repo fehlt.
- **Update-Dialog:** neue Blockart `Image` in `ReleaseNotes` für eine Zeile, die nur aus `![alt](url)` besteht. Erlaubt nur `https://raw.githubusercontent.com/JuliusFo/FerretSharp/…`, alles andere zeigt den Alt-Text. Weiterhin kein HTML aus dem Internet: gerendert wird ein `<img>`-Element mit `src`, `alt`, `loading="lazy"`, `max-width: 100%`. Lädt das Bild nicht (offline, VPN), zeigt `@onerror` den Alt-Text. Die WebView hat keine CSP, externe Bilder laden also ohne Änderung am Host.
- **Tests:** Parser (Bild-Zeile, fremder Host, `http`, Bild mitten im Text bleibt Text); Repo-Test, dass jedes im `CHANGELOG.md` verwiesene Bild existiert und relativ eingebunden ist.
- **Doku:** Regel in `docs/release.md` – zugeschnittene Ausschnitte statt ganzer Fenster, etwa 100–200 KB (PNG oder WebP; liegen für immer in der Git-Historie, das Velopack-Paket wird nicht größer), Alt-Text als lesbarer Satz, Aufnahme wie die README-Screenshots (`docs/e2e-testing.md`: eigene Instanz mit `--data-dir`, Beispiel-DB, `--lang=en`, CDP `Page.captureScreenshot`), nie echte Verbindungen oder Hosts.
- **Einführung:** Die Version mit der Unterstützung hat selbst noch keine Bilder in ihren Notizen (der Dialog der *installierten* Version zeigt die Notizen der neuen). Ab der nächsten zeigen ältere Installationen statt des Bildes „!Alt-Text“, bis sie aktualisiert sind – kosmetisch.
- Offen: Platz in der Reihenfolge (klein, unabhängig von allen anderen Paketen); helles/dunkles Bild je Theme (die README nutzt `-light`/`-dark`; im Dialog könnte die App die Variante passend zum Theme wählen, auf GitHub per `<picture>` – Vorschlag: zunächst nur eine Variante); Klick auf das Bild öffnet es groß (im Browser oder als Overlay) oder nichts.

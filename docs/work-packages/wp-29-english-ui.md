# WP-29 Englische Oberfläche → Release 3.19.0
Wunsch des Nutzers (2026-10-09): README, CHANGELOG und Screenshots auf GitHub sind englisch, die Oberfläche war nur deutsch. Entscheidungen des Nutzers: Englisch und Deutsch, **Standard Englisch** (auch für bestehende Installationen), Deutsch in den Einstellungen; `[Display]`-Namen aus dem C#-Projekt bleiben in der Windows-Sprache (das Projekt des Nutzers hat nur deutsche Ressourcen); Formatkultur bleibt vorerst (Backlog). Gebaut mit einem Workflow aus mehreren Agenten (Wunsch des Nutzers).
- **Phase 1 (von Hand):** typisierte resx je Bereich, vom SDK erzeugt (`Directory.Build.targets`, neutrale Sprache Englisch) statt `IStringLocalizer` – statischer Zugriff auch aus State-, Core- und ModelHost-Klassen, fehlender Schlüssel = Compilerfehler, keine neue Abhängigkeit (ADR 0017). `UiLanguage`/`AppSettings.Language`, `--lang=en|de`; die App setzt nur die UI-Kultur und gibt die Windows-Kultur ausdrücklich an `ModelHostRunner`/`ModelCache` (Cache-Schlüssel, `[Display]`). `TextFormat` (Format, Plural), Komponente `Fmt` (Platzhalter als Markup), Sprachauswahl in den Einstellungen, `<html lang>`. Tests: deutsche UI-Kultur für alle Testprojekte (`tests/Shared/UiCulture.cs`), `ResourceTests` je Textklasse (gleiche Schlüssel, keine leeren Texte, gleiche Platzhalter; ModelHost über die Integrationstests). Regeln und Glossar: `docs/localization.md`.
- **Phase 2 (Workflow, 7 Agenten parallel, je eigener Worktree und Branch):** UI Grid/Editieren, UI SQL/LINQ/Plan, UI Shell/Verbindungen/Workspaces, UI Schema/Modell/Vergleich, Core ClrModel + ModelHost, Core Query/Data/Schema, Core Oracle/Compare/Rest – 1.345 Schlüssel, ohne Merge-Konflikte (eine resx je Bereich). Deutsche Texte wortgleich übernommen (Skriptprüfung: 796 Texte wiedergefunden, der Rest hat jetzt Platzhalter oder ist eine Programmierfehler-Meldung, die regelgemäß englisch im Code steht).

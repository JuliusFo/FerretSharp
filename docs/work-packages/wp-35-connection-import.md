# WP-35 Verbindungen importieren und exportieren → Release 3.31.0
Frage eines Kollegen des Nutzers (2026-10-13), mit dem Nutzer als Paket geplant (Entscheidungen, Formate und Mockups in `docs/roadmap.md`), ADR 0025: Verbindungen aus einer anderen FerretSharp-Installation, aus DBeaver und aus SQL Developer übernehmen, Verbindungen an Kollegen weitergeben.
- Entscheidungen des Nutzers (2026-10-13): Passwörter nie mitnehmen; Duplikate standardmäßig überspringen, je Zeile überschreiben oder Kopie; Prod immer schreibgeschützt; einmalige Kopie statt geteilter Datei (Team-Workspace bleibt im Backlog); Umfang FerretSharp, DBeaver, SQL Developer (HORA im Backlog, der Nutzer fand keinen Export). Nach den Beispieldateien: Art aus dem Namen raten, geratene Verbindungen schreibgeschützt bis zur Wahl; den DBeaver-User aus `credentials-config.json` entschlüsseln (nur den User); Installationen automatisch finden (nur nachsehen, gelesen wird nach Klick); Kurzweg „Gruppe exportieren“ im Gruppenkopf; Projektname als Gruppe (außer `General`), ein DBeaver-Ordner geht vor. Ohne Agenten am Stück umgesetzt (Wunsch des Nutzers).
- Abweichung vom Plan: Der Schema-Vergleich fragt schon seit WP-20 selbst nach Passwörtern (`NeedsPassword`) – die neue Abfrage betrifft nur das Verbinden.
- Core (`Connections/Transfer`): `ConnectionImportReader` (Quelle am Inhalt: Zip → DBeaver-Export, JSON nach Form; bei einer `data-sources.json` die `credentials-config.json` daneben, Projekt aus dem Pfad), `DbeaverConnections` (`.dbp` und `data-sources*.json`, BASIC/URL, Typen `dev`/`test`/`prod` → Art, eigene Typen geraten, `read-only`, Ordner/Projekt → Gruppe, andere Datenbanken gezählt), `DbeaverCredentials` (nur `user` per `Utf8JsonReader`, Puffer überschrieben), `SqlDeveloperConnections` (BASIC/URL; TNS, OS-Anmeldung, Kerberos, Proxy, Rollen als „nicht unterstützt“; `password` nie gelesen), `FerretSharpConnections` (Export = `connections.json` + `format`, lokale Pfade nur auf Wunsch; Import liest auch eine fremde `connections.json`, neue Ids, neuere Formatversion abgelehnt), `JdbcUrl` (drei Thin-Formen, Zugangsdaten in der URL übersprungen), `ConnectionKindGuess`, `ConnectionInstallations` (DBeaver-Projekte, neuester SQL-Developer-`system`-Ordner numerisch, auch mit Versionsendung am Unterordner), `ConnectionImportPlan`/`ImportRow` (Auswahl, Art, User, Duplikat, Aktion, Gruppe, `Problem`, `Build`), `ImportJson`/`ImportLimits` (nachsichtig lesen, 16 MB, 10.000 Zip-Einträge). `ConnectionManager.SaveManyAsync` (einmal schreiben, ein `Changed`), `SetPassword(…, remember)`, Sitzungs-Passwörter, `ForgetSessionPassword`; `ActiveConnection` vergisst ein Sitzungs-Passwort bei ORA-01017. Texte in `ConnectionText`.
- UI: `ConnectionTransfer` (Singleton, Suchordner per `--import-appdata=` für E2E), `ConnectionExportSelection` (Gruppen wie die Verbindungsseite, Häkchen je Gruppe/Verbindung, Alle/Keine wirken auf die gezeigten), `ShellState.PendingPassword`/`RequestPassword` (bleibt auf der Seite, von der aus verbunden wurde), `ImportOpen`, `ExportRequest`; `WorkspaceLifecycle.ConnectAsync` fragt bei fehlendem Passwort. Komponenten `ConnectionImportDialog`, `ConnectionExportDialog`, `PasswordDialog`, `MoreMenu` („⋯“ im Seitenkopf und im Gruppenkopf – vor dem Kopf im Markup, weil die Rahmen der Zeilen am direkten Nachbarn hängen). „Importieren…“ auch im Leerzustand ohne Verbindungen. Texte in `ShellText`.
- Tests: Core 1720, UI 218, Integration 199 – darunter Core (`ImportReaderTests`, `ConnectionInstallationsTests`, `ConnectionImportPlanTests` mit anonymisierten Fassungen der Beispieldateien des Nutzers – erfundene Namen, Hosts und User; DBeaver-Credentials vom Test selbst verschlüsselt, mit erfundenem Passwort, das in keinem Ergebnis auftauchen darf –, `ConnectionManagerTests`, `ActiveConnectionTests`), UI (`ConnectionTransferTests`: Export-Auswahl, Passwortabfrage beim Verbinden, Sitzungs-Passwort).
- E2E (eigener Container `ferret-e2e-wp35`, eigene Instanz mit `--data-dir`, WebView2-Ordner und `--import-appdata` auf erfundene DBeaver- und SQL-Developer-Dateien, CDP, deutsch/hell und deutsch/dunkel): Installationen gefunden (DBeaver mit zwei Projekten, SQL Developer 24.3 statt 23.1); DBeaver-Vorschau mit Art, Prod-Schloss, TNS ausgegraut, Postgres ausgelassen, Ordner als Gruppe; Import ohne User → Hinweis und rote Felder, User eingetragen, eine Zeile abgewählt → zwei importiert, Prod schreibgeschützt, Gruppe „DBeaver“; SQL Developer: beide Verbindungen als „Vorhanden“ erkannt, Art „Test (geraten)“/„Sonstige (geraten)“ mit Schloss, Art gewählt → Schloss weg, Überschreiben behält Id und Gruppe; Verbinden ohne Passwort → Abfrage, Seite bleibt; falsches Sitzungs-Passwort → ORA-01017, „Erneut versuchen“ fragt wieder; richtiges → verbunden, Workspace-Session lädt eine Tabelle; Export-Dialog über „⋯“ (Gruppen-Häkchen „0 von 1“) und „Gruppe exportieren…“ (nur die Gruppe gewählt) – „Speichern unter“ nicht geöffnet (nativer Dialog). Log ohne `[ERR]`, kein Eintrag im Credential Manager (Sitzungs-Passwort), Container entfernt.
  - Gefunden und behoben: Überschreiben ersetzte die Gruppe der vorhandenen Verbindung durch die Vorgabe (jetzt bleibt sie, wenn die Quelle keine bringt); TNS-Einträge aus SQL Developer zeigten die ganze JDBC-URL (jetzt den Alias); Auswahl der Art zu schmal für „Sonstige (geraten)“; „…“ hinter jedem Häkchen (Spalte zu schmal, `text-overflow`).
  - Echte Mausklicks per `SendInput` kamen wie in WP-32/WP-33 nicht an (nur `pointermove`); geklickt per CDP `Input.dispatchMouseEvent`. Die Dialoge nutzen nur Knöpfe, Häkchen, Auswahllisten und Textfelder.
  - Nicht geprüft: eine echte, von DBeaver verschlüsselte `credentials-config.json` (bewusst nicht entschlüsselt, Prüfung durch den Nutzer), Export bis in die Datei (nativer Dialog; Inhalt durch die Core-Tests), „Datei wählen…“ (nativer Dialog).
- Offen (Backlog): TNS-Verbindungen importieren (Beispiele fehlen), HORA.
- Review (unabhängiger Agent über den ganzen Branch, Funde mit einem Probe-Programm bestätigt; auf Wunsch des Nutzers alle behoben, Vorschläge zu 2 und 3 vom Nutzer bestätigt):
  - H1: Ein Passwort „nur für diese Sitzung“ kam über *Duplizieren* in den Credential Manager (`GetPassword` liefert auch Sitzungs-Passwörter, der Verbindungsdialog speicherte es für die Kopie); *Bearbeiten* zeigte „Passwort unverändert“ ohne gespeichertes. Jetzt `ConnectionManager.GetStoredPassword` im Dialog. Dazu: Bearbeiten und Duplizieren verlangen kein Passwort mehr (es wird beim Verbinden abgefragt), nur „Neu“ und „Testen“.
  - H2: Duplikate wurden ohne Absicht überschrieben – „alle“ wählte sie mit „Überschreiben“, ein getippter User machte eine gewählte Zeile zum Duplikat –, und zwei Zeilen auf dieselbe Verbindung ergaben zwei Einträge mit einer Id. Jetzt: „alle“ wählt nur normale Zeilen (`ConnectionImportPlan.SelectAll`/`PlainRows`), ein getippter User, der die Zeile zum Duplikat oder zur Wiederholung macht, wählt sie ab, zwei Überschreibungen derselben Verbindung sind ein `Problem` (Text `ImportSameTargetTwice`), `SaveManyAsync` lehnt doppelte Ids ab.
  - M3: Überschreiben verlor das Default-Schema, machte Prod/schreibgeschützt beschreibbar (DBeaver-Typ `dev`) und ersetzte die eigenen lokalen Pfade durch die aus einer fremden `connections.json`. Jetzt lockert Überschreiben nie den Schutz (`ImportRow.ReadOnly` mit `Overwrites`, Schloss mit eigenem Tooltip, unter der Umgebung „vorhanden als Produktion“), Default-Schema, lokale Pfade und App-Umgebung der vorhandenen Verbindung bleiben.
  - M4: Die Passwortabfrage sprang zur Seite eines früheren `Connect`, auch wenn „Statements der App“ oder der Schema-Vergleich selbst verbanden. Jetzt nimmt der Lifecycle die Herkunft genau einmal (`ShellState.TakeConnectOrigin`); `PasswordRequest.ShowWhenConnected` entscheidet, ob danach der Explorer kommt oder die Seite bleibt.
  - M5: Ausnahmen entkamen dem Import-Dialog (außerhalb jeder ErrorBoundary): FerretSharp-Datei mit Adresse ohne `type` (`NotSupportedException`), IO-Fehler beim Auflisten einer Installation; ein Fehler bei DBeaver versteckte SQL Developer. Jetzt als `ConnectionImportException`, Suche je Programm getrennt, im Dialog ein letzter Auffang mit Log.
  - Klein: rohe JDBC-URLs mit `user/passwort@` in der Vorschau (`JdbcUrl.ForDisplay` schon beim Lesen); geratene Art ließ sich nicht direkt bestätigen (eigene Option für die Vermutung); UTF-8-BOM abgelehnt; ungültige Werte (Port 99999) scheiterten erst beim Speichern für alle (jetzt in der Vorschau „nicht unterstützt“ mit dem Grund, Meldung ohne Parameter-Anhang); Wiederholungen in der Datei (Status „Doppelt in der Datei“, nicht gewählt); neuere Formatversion vor dem Deserialisieren geprüft; Zip mit Gesamtgrenze 64 MB und Abbruch; `MoreMenu` über `PopoverMenu` (Esc, bleibt im Fenster).
  - Tests: Core 1734 (`ImportReviewTests`, je Fund mindestens einer), UI 220 (Seite bleibt bei eigenem Verbinden, Herkunft nur einmal), Integration 199. E2E (eigene Instanz, deutsch/hell): „⋯“ als Popover, getippte User machen Zeilen zu „Vorhanden“ und wählen sie ab, „alle“ wählt nur die normale Zeile, geratene Art mit eigener Option und nach Bestätigung ohne Schloss, „vorhanden als Test“ – dabei gefunden: der Hinweis stand auch an nicht gewählten Duplikaten (jetzt nur, wenn die Zeile wirklich überschreibt). Log ohne `[ERR]`.

## Planung (aus `docs/roadmap.md`)
Frage eines Kollegen des Nutzers (2026-10-13), mit dem Nutzer als Paket definiert (2026-10-13), umgesetzt (Protokoll in `docs/work-packages.md`, ADR 0025; Abweichung: der Schema-Vergleich fragte schon selbst nach Passwörtern, die Abfrage betrifft nur das Verbinden). Ziel: Verbindungen aus einer anderen FerretSharp-Installation, aus DBeaver und aus SQL Developer übernehmen, statt sie von Hand anzulegen oder `connections.json` zu kopieren (überschreibt die eigenen, Passwörter fehlen). Dazu ein Export, um Verbindungen an Kollegen weiterzugeben.
- Entscheidungen des Nutzers (2026-10-13, bei der Planung):
  - **Passwörter nie mitnehmen**, weder beim Export noch beim Import (DBeaver verschlüsselt sie mit einem bekannten festen Schlüssel, SQL Developer mit einem beim Export gewählten). Der Nutzer gibt sie beim ersten Verbinden ein, sie landen wie immer im Credential Manager.
  - **Duplikate** (gleiche Adresse und gleicher User) werden standardmäßig übersprungen; in der Vorschau je Zeile änderbar: überspringen, überschreiben, als Kopie anlegen.
  - **Prod bleibt geschützt:** Importierte Verbindungen der Art Prod sind immer schreibgeschützt, egal was die Quelle sagt.
  - **Einmalige Kopie, keine geteilte Datei.** Der Team-Workspace im Repository (`.ferretsharp/`, immer aktuell wie die Anzeigespalten aus WP-31) bleibt im Backlog; dieses Paket ist der kleinere erste Schritt.
  - **Umfang:** FerretSharp, DBeaver, SQL Developer. HORA (KeepTool) nicht: Der Nutzer findet dort keinen Export und klärt das mit den Kollegen, die HORA nutzen (Backlog).
  - **Art ohne Angabe der Quelle** (2026-10-13, nach den Beispieldateien; SQL Developer kennt keine Umgebungsart): Die Vorschau rät die Art aus dem Namen (`prod`/`prd`/`live` → Prod, `test`/`tst`/`qs` → Test, `dev`/`entw` → Dev, sonst Other). Jede Verbindung, deren Quelle keine Art angibt, kommt schreibgeschützt herein, bis der Nutzer die Art in der Vorschau wählt – sonst wäre eine Prod-Verbindung als Other beschreibbar.
  - **User aus DBeaver entschlüsseln** (2026-10-13): Den User gibt es nur in der verschlüsselten `credentials-config.json` (siehe unten). FerretSharp entschlüsselt sie und übernimmt nur `user`; ein gespeichertes Passwort wird sofort verworfen, nie angezeigt, gespeichert oder geloggt. Bei der Entwicklung nie echte Credential-Dateien entschlüsseln: Testdaten selbst erzeugen (erfundener User, ohne Passwort; für den Test „Passwort wird verworfen“ ein erfundenes).
- Quellen (an echten Beispieldateien geprüft, 2026-10-13; sie gehen nur anonymisiert – erfundene Namen, Hosts und User – als Testdaten ins Repository):
  - FerretSharp: eigener Export oder eine fremde `connections.json`; alles übernehmbar.
  - DBeaver: Projektexport `.dbp` (Zip mit `projects/<Projekt>/.dbeaver/data-sources.json`, `credentials-config.json`, `meta.xml` mit Rechnername und IP des Exportierenden) oder die rohe `…\DBeaverData\workspace6\General\.dbeaver\data-sources.json` – beides lesen. `connections` ist ein Objekt (Id → Verbindung), nur `provider: oracle`. In `configuration`: `host`, `port` (String), `database` (Service-Name oder SID je `provider-properties.@dbeaver-sid-service@` = `SERVICE`/`SID`), `@dbeaver-connection-type@` (`BASIC`; TNS ohne Beispiel), `url`, `type` → Id in `connection-types` derselben Datei (`dev`/`test`/`prod` → Art, eigene Typen → Other), `folder` → Gruppe (Beispiel ohne Ordner). **Der User steht nicht in `data-sources.json`**, sondern nur in der verschlüsselten `credentials-config.json` (AES-128-CBC mit DBeavers festem, öffentlich dokumentiertem Schlüssel, die ersten 16 Byte sind der IV; JSON Id → `#connection` → `user`/`password`). Im Beispiel ist laut Dateigröße nur der User darin, kein Passwort.
  - SQL Developer: JSON aus „Export Connections“: `connections[]` mit `name`, `type: jdbc` und `info` (alle Werte Strings): `OracleConnectionType` (`BASIC`; TNS ohne Beispiel), `hostname`, `port`, `serviceName` bzw. `sid`, `user`, `customUrl` (auch bei BASIC gefüllt), `SavePassword`/`NoPasswordConnection`, `OS_AUTHENTICATION`/`KERBEROS_AUTHENTICATION`/`IS_PROXY` (→ Hinweis „nicht unterstützt“). Keine Umgebungsart. Die `connections.json` der Installation hat **dasselbe Format** (an einer echten Datei geprüft, 2026-10-13); mit `SavePassword: "true"` steht dort zusätzlich `password` (verschlüsselt mit einem rechnerbezogenen Schlüssel) → der Leser greift das Feld nie an. `NoPasswordConnection` ist auch bei gespeichertem Passwort `"TRUE"` und taugt nicht als Merkmal. Auch die Variante mit `sid` statt `serviceName` ist damit belegt.
  - TNS: In keinem Beispiel. Liefert der Nutzer keine Beispiele nach, zeigt die Vorschau solche Einträge als „nicht unterstützt“.
  - Installationen (an einer echten Dateiliste geprüft, 2026-10-13):
    - DBeaver: `%APPDATA%\DBeaverData\workspace6\<Projekt>\.dbeaver\data-sources.json`, je Projekt **eine** Datei. Neben dem Standardprojekt `General` kann es weitere Projekte geben, auch mit Leerzeichen und Umlauten im Namen → alle Projekte durchsuchen.
    - SQL Developer: `%APPDATA%\SQL Developer\system<Version>\o.jdeveloper.db.connection\connections.json`; der Unterordner hat (23.x wie 24.x) **keine** Versionsendung. Nach einem Update bleiben die alten `system*`-Ordner liegen → den neuesten nehmen, Version numerisch vergleichen (nicht als Text).
- Entscheidungen zur UI (2026-10-13, an Mockups abgestimmt):
  - **Passwortabfrage beim Verbinden:** Heute endet Verbinden ohne gespeichertes Passwort mit dem Fehler `NoPasswordSaved` (`ActiveConnection`, `WorkspaceSessions`). Nach einem Import hat keine Verbindung ein Passwort → kleiner Dialog „Passwort für …“ mit Häkchen „Im Credential Manager speichern“ (gesetzt); auch für den Schema-Vergleich (`NeedsPassword`).
  - **Import:** Knopf „Importieren…“ neben „+ Neue Verbindung“ auf der Verbindungsseite. Dialog: oben die Quelle – gefundene Installationen von DBeaver und SQL Developer mit Anzahl der Verbindungen, daneben „Datei wählen…“ (`.json`, `.dbp`). **Installationen automatisch finden:** nur prüfen, ob die Ordner existieren; gelesen wird erst nach Klick. Darunter die Vorschau: Häkchen, Name, Art als Auswahl (Markierung „geraten“), Adresse, User, Status (Neu / Duplikat mit Aktion überspringen-überschreiben-Kopie / nicht unterstützt, dann nicht wählbar), Schloss bei schreibgeschützt. Feld „Gruppe für Verbindungen ohne Gruppe“, vorbelegt mit der Quelle. Hinweis „Passwörter werden nicht übernommen“. Knopf „N importieren“.
  - **Export:** Menü „⋯“ im Kopf der Verbindungsseite → „Exportieren…“. Dialog: Verbindungen nach Gruppen wie auf der Verbindungsseite, Häkchen je Gruppe (wählt alle; Anzeige „1 von 2“) und je Verbindung, Suchen/Alle/Keine, vorausgewählt alles. Häkchen „Pfade dieses Rechners mitnehmen (C#-Projekt, Skriptordner)“, standardmäßig aus; Hinweis „Passwörter werden nie exportiert“. „N exportieren…“ → Speichern unter.
  - **Gruppe bei DBeaver-Projekten:** Ein DBeaver-Ordner der Verbindung wird zur Gruppe. Ohne Ordner wird der Projektname zur Gruppe; nur für das Standardprojekt `General` gilt das Feld „Gruppe für Verbindungen ohne Gruppe“.
  - **Kurzweg im Gruppenkopf:** Menü „⋯“ im Gruppenkopf der Verbindungsseite → „Gruppe exportieren…“ öffnet denselben Dialog, nur mit dieser Gruppe gewählt.

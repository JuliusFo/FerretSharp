# Fix: Name der Cache-Datei der Code-Verwendung ohne Ordner
Befund aus dem Code-Review von `fix-suggested-file-names.md` („vorher schon da“), vom Nutzer am 2026-11-01 als eigener Branch entschieden. Branch `fix/code-usage-cache-name`.
- **Lücke:** `CodeUsageBuilder.CacheFileName` setzte den `AssemblyName` aus der Projektdatei ungeprüft vor `.{mvid}.{set}.json`. Ein `AssemblyName` mit `..\` oder `../` schrieb die Cache-Datei außerhalb des Cache-Ordners, einer mit `:` oder ein Gerätename wie `NUL` ließ das Schreiben scheitern (still, der Cache ist nur eine Abkürzung). Quelle ist das selbst gewählte Projekt des Nutzers, dessen Code ohnehin läuft – sicherheitlich gering, aber fremde Namen werden nie ungeprüft zu einem Pfad.
- **Fix:** Der Name geht durch `SuggestedFileName.Of`. Entscheidung: keine eigene Regel. Was `Of` über Windows' Regeln hinaus ersetzt (`%`, Bidi-Steuerzeichen), schadet hier nicht – ein solcher Assembly-Name verliert nur einmal seinen Cache-Eintrag –, und eine zweite Regel für dieselbe Frage („ein Name als ein Dateiname“) liefe auseinander. Übliche Namen (`MyApp.Data`) bleiben unverändert, vorhandene Cache-Dateien gelten weiter.
- **Länge:** `Of` kürzte auf 255 Zeichen, danach kamen 47 Zeichen Suffix dazu – ein Name über 208 Zeichen hätte nie gespeichert werden können. `Of` hat dafür einen optionalen Parameter `maxLength` (Standard 255, `SuggestedFileName.MaxLength` jetzt öffentlich); der Builder übergibt 255 minus Suffix. Kürzen im Builder hätte das Schneiden ohne halbes Surrogatpaar, das Entfernen von Punkten am Ende und die Geräteprüfung nach dem Schnitt verdoppelt. Zwei lange Namen mit gleichem Anfang teilen sich danach beim Aufräumen das Limit von drei Builds je Assembly – vernachlässigbar.
- Tests (`SolutionAndBuilderTests`): `The_assembly_name_becomes_one_file_name_in_the_cache_folder` (`MyApp.Data` unverändert; `../../x`, `..\..\x`, `..`, `NUL`, `C:x`: der Dateiname beginnt mit dem erwarteten Namen und liegt direkt im Cache-Ordner) und `A_long_assembly_name_is_cut_to_leave_room_for_build_and_set`. Ohne den Fix scheitern alle Fälle außer `MyApp.Data`.

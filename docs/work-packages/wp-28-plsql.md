# WP-28 Prozeduren, Funktionen und Packages ansehen → Release 3.17.0
Wunsch des Nutzers (2026-10-08), Stufe 1 „nur ansehen“; Ausführen und Bearbeiten/Kompilieren bleiben draußen (Backlog). Plan mit dem Nutzer abgestimmt (2026-10-08), alle Vorschläge übernommen:
- **Explorer:** Umschalter „Tabellen | PL/SQL“ statt eigener Gruppe oder gemischter Liste (eine Gruppe läge unter 425+ Tabellen ganz unten). Die Namenssuche filtert den aktiven Bereich, ein Hinweis nennt Treffer im anderen („3 Treffer unter PL/SQL“, Klick wechselt). Der Bereich gilt je Verbindung für die Sitzung, nicht gespeichert.
- **Hervorhebung:** Monaco nur lesend mit eigener kleiner PL/SQL-Grammatik (Monacos `sql` ist T-SQL und kennt `ELSIF`/`LOOP`/`PACKAGE` nicht) – große Packages, Zeilennummern, Ctrl+F, Fehler-Marker. Nachtrag in ADR 0011.
- **Volltextsuche:** im Objekt über Monacos Ctrl+F; schemaweit über „Quelltext“ neben dem Suchfeld (Enter, mindestens 3 Zeichen, nur eigenes Schema, höchstens 500 Zeilen, abbrechbar).
- **Trigger ja, Typen nein** (Backlog). **Andere Schemas** über Synonyme wie bei Tabellen.
- Umgesetzt:
  - Core (`Schema/PlSqlObjects.cs`, `PlSqlArguments.cs`, `Oracle/OracleSchemaReader.PlSql.cs`; Unit- und Integrationstests): `PlSqlObjectSummary` (ein Eintrag je Package mit Status von Spezifikation und Body, `IsDisabled` für Trigger), `PlSqlRef` mit Art (Trigger haben einen eigenen Namensraum), `PlSqlSource` (eine Zeile je `ALL_SOURCE.LINE`, Zeilenende abgeschnitten → Zeile n im Editor = `LINE` n = Zeile in `ALL_ERRORS`; `IsWrapped`), `PlSqlSubprogram`/`PlSqlParameter`, `PlSqlError`, `PlSqlObjectInfo` (+ `TriggerInfo`), `SourceHit`. `ISchemaReader`: `GetPlSqlObjectsAsync`, `GetPlSqlInfoAsync`, `GetSourceAsync` (`FetchManyRows`), `GetSubprogramsAsync`, `GetErrorsAsync`, `GetDependenciesAsync(PlSqlObjectSummary)`, `SearchSourceAsync`; `GetSynonymTargetsAsync` liefert jetzt `SynonymTargets` (Tabellen und PL/SQL aus **einer** Abfrage über `ALL_SYNONYMS`). `SchemaCache.PlSqlObjects`/`FindPlSql` (auch über den Typ aus `ALL_DEPENDENCIES`, `PACKAGE BODY` → Package), Merge wie bei Tabellen. `TabState.PlSql` (`PlSqlTabState`, `PlSqlView`). `LikePattern` (Escaping aus dem `QueryBuilder` herausgelöst). Nur SELECTs auf `ALL_*`; `ReadOnlyTests` decken die neuen Texte ab, keine Änderung an der Lesesperre, kein ADR.
  - UI: `PlSqlTab` (State) und `PlSqlTabView` mit `PlSqlHeader`, `PlSqlSourceView` (Monaco `ReadOnly`, Sprache `plsql`, Marker aus `PlSqlMarkers`), `PlSqlParametersView`, `PlSqlErrorsView` (Klick → `PlSqlTab.ShowSource`), `PlSqlDependenciesView`. `DetailViewBase` aufgeteilt: `LoadingViewBase<T>` (Laden, Abbruch, `Version`) mit `DetailViewBase<T>` (Tabelle) und `PlSqlViewBase<T>`. `DependencyList` gemeinsam für Tabellen und PL/SQL – PL/SQL-Objekte sind jetzt auch aus den Abhängigkeiten einer Tabelle Links. Explorer mit `ExplorerList`/`SourceSearch` (State, testbar), `ShellState.OpenPlSql` (vorhandenen Tab wiederverwenden, Ansicht oder Zeile), `RemoveVanishedTabs` nach dem Schema-Refresh. `MonacoEditor`: `ReadOnly`, `RevealAsync` wartet auf den Editor.
  - Beispiel-DB: `tools/sample-db/07-plsql.sql`.
- Oracle-Erkenntnisse (per Integrationstest bzw. im Container belegt, Fallen heute in `.claude/rules/plsql-dictionary.md`): Oracle 23 legt für Unterprogramme **ohne Parameter keine Zeile** in `ALL_ARGUMENTS` an (ältere Versionen eine Platzhalterzeile) → Liste der Unterprogramme aus `ALL_PROCEDURES`. Den Body eines fremden Packages zeigt `ALL_SOURCE` mit `EXECUTE` nicht (leer statt Fehler). `CREATE` mit Kompilierfehlern liefert in ODP.NET ORA-24344. Ein Package mit ~5.500 Konstanten scheitert an PLS-00123 (für das Beispiel-Skript).
- Gemessen (eigener Container, ~33.000 öffentliche Synonyme, 150 Tabellen und 150 Prozeduren mit Grant): erweiterte Synonym-Abfrage 1,35 s statt 1,2 s; zwei getrennte Abfragen hätten die Zeit etwa verdoppelt. Package mit 6.002 Zeilen öffnet in 0,9 s (lokal).
- E2E (eigener Container `ferret-wp28-e2e` mit `New-SampleDb.ps1`, eigene Instanz, echte Windows-Maus über `realclick.ps1`, CDP-Tastatur, hell und dunkel): Umschalter, Liste (ungültig rot, deaktivierter Trigger grau, Kennzeichen), PKG_ALT → Spezifikation, Fehler (2), Klick → Body Zeile 4/Spalte 23 mit Unterstreichung und Hover; Parameter von PKG_RECHNUNG (Überladungen, IN OUT, `KUNDEN%ROWTYPE`, `SYS_REFCURSOR`, Default); PKG_KONSTANTEN (6.002 Zeilen); verschlüsselte Prozedur (Hinweis); Trigger mit Kopf und Tabellen-Link → RECHNUNG › Abhängigkeiten → Link auf PACKAGE BODY öffnet den Body; Quelltextsuche `faellig_am` → 2 Treffer im Trigger, Klick auf Zeile 7 setzt den Cursor auf den Treffer; Tippen zeigt den Nur-Lesen-Hinweis; Ctrl+F; F5 nach Änderung des Triggers in der DB (Umlaute); Objekt gelöscht + Schema-Refresh → Tab weg; Neustart stellt alle PL/SQL-Tabs mit Ansicht wieder her; Treffer-Hinweis in beide Richtungen. Log ohne `[ERR]`/`[WRN]`.
  - Gefunden und behoben: Monaco zeigt Marker in Nur-Lesen-Editoren standardmäßig nicht (`renderValidationDecorations`); abgeschnittener Platzhalter; springende Spaltenbreiten der Parameter-Tabellen.
  - Nicht per E2E: Objekte anderer Schemas über Synonyme (Integrationstest mit FERRET_OTHER), Abbrechen einer langen Quelltextsuche.

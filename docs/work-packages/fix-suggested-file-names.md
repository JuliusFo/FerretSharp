# Fix: vorgeschlagene Dateinamen ohne Ordner
Befund aus dem Code-Review von WP-68, im Backlog seit 2026-10-31; vom Nutzer am 2026-11-01 angestoßen. Branch `fix/suggested-file-names`.
- **Lücke:** Der Speichern-Dialog übernahm den vorgeschlagenen Namen ungeprüft als `SaveFileDialog.FileName`. Gebaut wird er aus Namen der Datenbank (Tabelle, Spalte, Synonym, Index, Grant-Ziel: DDL-Entwurf, Export, LOB) oder des Projekts (Modelldatei) – gequotet darf ein Oracle-Name alles enthalten. Ein `\`, `/` oder `..` darin ließ den Dialog in einem anderen Ordner starten (etwa `Startup`), ein Gerätename wie `NUL` hätte ins Leere geschrieben. Gespeichert wurde erst nach Klick des Nutzers, der Ordner stand im Dialog; der Name einer fremden Datenbank ist trotzdem fremde Eingabe.
- **Fix:** `Core/IO/SuggestedFileName.Of` macht aus dem Vorschlag einen Dateinamen im Ordner des Dialogs: von Windows verweigerte Zeichen (Trenner, `:`, `<>"|?*`, Steuerzeichen) → `_`, Punkte und Leerzeichen am Ende weg, vor Gerätenamen (`CON`, `NUL`, `COM1` … auch mit Endung) ein `_`, über 255 Zeichen vor der Endung gekürzt, leer → `_`. Feste Windows-Regeln statt `Path.GetInvalidFileNameChars` – Core läuft auch unter Linux, dort kennt das nur `/`.
- Zentral in `FileSaveService.AskAsync` (App), also für jeden Aufrufer von `IFileSaveService` (Speichern als Text, Bytes und Export im Hintergrund); die Aufrufer bauen ihre Namen weiter wie bisher. Tests: `SuggestedFileNameTests`.
- Sonst gelangen Namen aus der Datenbank nirgends in einen Pfad (`Path.Combine` in Core und UI durchgesehen).

# Klein: Verbindung für einen Link selbst wählen → Release offen
Wunsch des Nutzers (2026-10-15, nach 3.35.3): Passt keine Verbindung zu einem Link, soll man die Ziel-Verbindung selbst wählen können – oder auch, wenn man sie bewusst ändern möchte. Entscheidung des Nutzers: so umsetzen wie vorgeschlagen, das Merken der Zuordnung in den Backlog. Branch `feat/link-choose-connection`. Entscheidung und Sicherheit: Nachtrag zu ADR 0026.
- **Core:** `LinkConnectionMatch.Suggestions(profiles, link)` – die passenden Verbindungen (`Find`: Treffer oder Kandidaten), dann die mit dem Schema des Links (`EffectiveSchema == Owner`), je in der Reihenfolge der Verbindungsliste (`ConnectionSearch.Group`). Test `Suggestions_are_the_fitting_connections_then_those_of_the_links_schema`.
- **UI State:** `LinkTargetChoice` (je `IncomingLink`): `Choosing` (ohne Treffer gleich, sonst nach „Ändern…“/„Andere Verbindung…“), `Chosen`/`Target` (ohne Treffer nichts vorausgewählt; „Ändern…“ behält den Treffer gewählt), `Suggested`/`Others` (durchsucht wie der Umschalter, `ConnectionSearch.Matches`), `Elsewhere` (Ziel ist weder Treffer noch Kandidat → Hinweis mit Name und Adresse aus dem Link), `AddressDiffers` (Warnung nur, solange der Namens-Treffer das Ziel ist), `CanChooseOther`. Tests `LinkTargetChoiceTests`.
- **Dialog:** `LinkOpenDialog` zeigt die Liste im Dialog selbst (`SearchBox`, Überschrift „Vorschläge“, dann die Gruppen; Liste scrollt bei 260 px) statt eines Popovers über dem Modal – Esc im leeren Suchfeld schließt wie bisher den Dialog. „Öffnen“ erscheint, sobald es überhaupt Verbindungen gibt, gesperrt bis zur Wahl; „Schließen“ nur bei ungültigem Link oder ohne Verbindungen. Texte `Link_Change`, `Link_OtherConnection`, `Link_ChooseConnection`, `Link_Suggested`, `Link_OpensElsewhere` (EN/DE).
- Öffnen auf der gewählten Verbindung nutzt den bestehenden Weg (`ShellState.OpenLinkIn`): Tabelle im eigenen Schema oder als Synonym, Filter und Sortierung auf fehlenden Spalten deaktiviert, fehlende Tabelle mit Meldung.
- E2E (eigener Container `ferret-e2e-links` auf Port 1532, danach entfernt; Scratch-Datenordner mit „Sample DEV“/„Sample PROD“ auf dem Container und „Kasse TEST“ auf `127.0.0.1:1`; Links per zweitem Start mit `--data-dir`; Passwort ohne Speichern): Link einer fremden Verbindung → Liste mit „Vorschläge“ (beide Sample-Verbindungen, Schema FERRET) und Gruppe Kasse, Fokus auf „Abbrechen“, „Öffnen“ gesperrt; Suche „kasse“ engt ein, ✕ leert; Wahl „Sample DEV“ → Hinweis „Der Link zeigt auf Kollegen-DB (10.0.0.9:1521/OTHER); geöffnet wird auf Sample › Sample DEV.“ → Passwort → Tab KUNDEN mit Filter. Passender Link → Verbindung mit „Ändern…“ → Liste mit dem Treffer gewählt, Wahl PROD → Hinweis. Zwei Kandidaten → „Andere Verbindung…“ → Suchfeld hat den Fokus; Esc leert die Suche, das zweite Esc schließt den Dialog. Deutsch/dunkel, Englisch/dunkel, hell per Emulation. Log ohne `[ERR]`/`[WRN]` und ohne Link-Inhalt.
- Gefunden im E2E: Nach „Ändern…“ fiel der Fokus auf die Seite (der Knopf verschwindet) → das Suchfeld bekommt ihn; „Andere Verbindung…“ stand 8 px eingerückt neben den Kandidaten (`.link-other`).
- Klicks per Windows-Eingabe (`SendInput`) kamen in dieser Sitzung nicht an (Rückgabe 2, App-Fenster vorne und unter dem Punkt, kein `mousedown`) – geprüft per CDP-Eingabe. Das Klick-Skript prüft jetzt vor dem Klick auch das Fenster unter dem Punkt: Beim ersten Versuch lag das Testfenster auf einem anderen Bildschirm (negative Koordinaten).
